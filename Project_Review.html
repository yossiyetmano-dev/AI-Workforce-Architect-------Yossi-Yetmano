1. Executive Summary

This project presents the implementation of a production-ready, enterprise-grade Multi-Agent System based on n8n, Ollama/OpenAI GPT models, Google Sheets, and Pinecone Vector Store for the automated management of an electronic components distribution company.

Design Principles:

  • Snake Architecture: Synchronous, one-way flow without Switch/Merge nodes
  • Pipeline Routing: Orchestrator determines agent order based on request type
  • Skip Conditions: Each agent can skip itself if not relevant
  • Sub-Workflows: Each agent is an independent workflow called by the Orchestrator
  • Google Sheets Backend: All customer data, price lists, and logs
  • Human-in-the-Loop (HITL): Approval workflow for high-value decisions

System includes 9 agents:

Orchestrator → Technical → Pricing → CRM → Procurement → Logistics → Finance → Admin → HITL

Results:

  • ✅ Full automated flow from RFQ to invoice
  • ✅ Automatic handling of RFI (information requests)
  • ✅ Smart routing based on Pipeline
  • ✅ Complete logging for every action in Google Sheets
  • ✅ Human approval for high-value POs ($30,000+)
  • ✅ Vector store search for technical datasheets
  • ✅ Robust error handling with CEO notifications
  • ✅ Multi-currency support (USD suppliers, ILS customers)

2. Company Background & Overview

2.1 Company Profile

Company Name: Electro-Tech Representatives Ltd. (Pseudonym)

Industry: Marketing, import, distribution, and technical support of advanced electronic components (processors, CMOS Image Sensors, ADC/DAC converters, optical transceivers, Ethernet switches, micro motors) for the defense and medical markets in Israel.

Business Model: Electro-Tech acts as an intermediary between global component manufacturers (suppliers) and Israeli customers (defense contractors, medical device companies, industrial manufacturers). The company purchases components in USD from suppliers and sells them in ILS to customers, adding markup and managing the entire supply chain from quote to invoice.

3. Business Process Analysis

3.1 Main Flow - RFQ (Request for Quote)

Customer sends request (Email / Webhook)
         ↓
Orchestrator: Identifies request type, determines Pipeline
         ↓
Technical Agent: Validates part number / RAG search
         ↓
Pricing Agent: Calculates price (USD → ILS)
         ↓
CRM Agent: Creates Quote, sends email, logs
         ↓
Admin Agent: Logs all information
         ↓
Complete: Email confirmation to customer

3.2 Secondary Flow - PO (Purchase Order)

Customer sends PO (Email / Webhook)
         ↓
Orchestrator: Identifies PO → PO Pipeline
         ↓
Pricing Agent: Validates price against Quote
         ↓
CRM Agent: Approves PO, sends email
         ↓
Procurement Agent: Creates PO to supplier (USD)
         ↓
Logistics Agent: Confirms goods receipt
         ↓
Finance Agent: Creates invoice (ILS), sends email
         ↓
Admin Agent: Logs all information
         ↓
Complete: Email confirmation to customer

3.3 Third Flow - RFI (Request for Information)

Customer sends technical information request
         ↓
Orchestrator: Identifies RFI → Pipeline: Technical → Admin
         ↓
Technical Agent: Searches Vector Store
         ↓
Admin Agent: Logs
         ↓
Complete: (No quote, no PO, no invoice)

3.4 Fourth Flow - NPI (New Product Introduction)

Supplier sends new part information
         ↓
Orchestrator: Identifies NPI → Pipeline: Technical → Admin
         ↓
Technical Agent: Validates part in catalog
         ↓
Admin Agent: Updates inventory master
         ↓
Complete: (No quote, no PO, no invoice)

4. System Architecture

4.1 Snake Architecture Structure

ORCHESTRATOR (MAIN WORKFLOW)

Webhook / Gmail Trigger → Guardrail → Orchestrator (AI) → Code
         ↓
Call Technical → Code → Call Pricing → Code → Call CRM → Code
         ↓
Call Procurement → Code → Call Logistics → Code → Call Finance
         ↓
Code → Call Admin → Code → Email → Respond

Each Agent = Independent Sub-Workflow
Each Code Node = State transfer / Skip decision

4.2 Pipeline Determination

Request Type Pipeline
RFI["Technical", "Admin"]
RFQ["Technical", "Pricing", "CRM", "Admin"]
PO["Pricing", "CRM", "Procurement", "Logistics", "Finance", "Admin"]
NPI["Technical", "Admin"]

4.3 Skip Logic

Each agent executes a Skip if:

  • It is not in the Pipeline
  • Request type is not relevant (e.g., Logistics in RFQ → SKIP)
  • Previous agent returned an error / Rejection

Example: In RFQ, Logistics, Finance, Procurement skip automatically.

4.4 Human-in-the-Loop (HITL) Architecture

Agent Detects Need for Approval
         ↓
Call HITL_Approval_Manager Sub-Workflow
         ↓
Send Approval Email with Approve/Reject Buttons
         ↓
Wait for Human Response (Webhook)
         ↓
Capture Response → Resume Workflow
         ↓
APPROVED → Continue Execution
REJECTED → Stop Execution

Triggers for HITL Approval:

  • Procurement Agent: totalCostUSD > $30,000
  • CRM Agent: Credit limit exceeded OR price mismatch
  • Pricing Agent: Price override required

4.5 Error Handling Architecture

Error Trigger (Catches ALL workflow errors)
         ↓
Code: Extract execution context (sessionId, workflowName, failedNode)
         ↓
Google Sheets: Log error to Admin_Audit_Log
         ↓
Gmail: Send error notification to CEO
         ↓
Complete: Error logged and reported

6. Prompt Engineering - Detailed Prompts

6.1 Orchestrator Prompt - Key Sections

You are the Chief Routing Orchestrator for Electro-Tech Representatives Ltd.

Available Agents:
- Technical: Validates parts in catalog / NPI check

- CRM: Creates quotes, checks inventory
- Procurement: Creates purchase orders with suppliers

- Admin: System maintenance, database logging, and quote storage

Tools:

2. Answer questions with a vector store - Pinecone datasheets

Rules:
- If partNumber provided → check catalog
- If partNumber missing → search vector store
- PO requests → SKIP (already approved)
- RFI requests → search vector store and return information

You are the Computational Pricing Analyst for Electro-Tech Representatives Ltd.

Steps:

3. Base Cost USD = Unit Price × Quantity
4. Markup 30%
5. Volume discounts (5-15%)

- urgency_premium_rate

You are the Enterprise Financial Controller for Electro-Tech Representatives Ltd.

1. RFQ/SKIP → do not invoice
2. Order/PO + goodsArrived=true → invoice
3. ILS Only - no USD on invoices
4. Payment terms: Net 30 (standard), Net 60 (defense)
5. Due Date = Today + Payment Terms

ILS Currency Rule: All customer-facing invoices must be in ILS (₪).
Never write USD symbols ($) on the customer invoice.
